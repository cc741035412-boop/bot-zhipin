## 2026-11-15 LB8：Raycast 版式 + Grok 灵动

31. **首页和详情页的版式参考 Raycast Store，只借鉴结构与质感；深色主打；保留 Grok Bot 的灵动和颜色**（用户 2026-11-15 定：看过 5 个参考后选了 raycast.com/store 这个方向，并要求「保留 grokbot 的灵动跟颜色」）。上一版的「大舞台卡片」功能齐全，但版面拥挤、质感粗糙。新版照着实测规格对齐骨架：悬浮玻璃导航条、两排图标砖墙、80px 大标题、搜索框、精选三张大卡、分段排序 + 分类筛选的工具栏、两列细边卡片、悬停只淡入一层光不位移。Grok 的部分全部留下并顶到前面：砖墙里站的是 9 只会动的彩色吉祥物，背后是橙、紫、青绿的极光；每个 Bot 的官方色透到自己的卡片上（按钮、砖里的柔光、悬停光晕、描边）；悬停、戳、睡醒、入场、漫画气泡照旧。主题跟随系统，深色按 Raycast 的质感做到位，浅色用同一套结构换暖色 token。
    - **不复制** Raycast 的代码、图标、文案和红色光束背景；数值来自对公开页面的实测，实现全部自写。
    - **放弃了什么**：236px 的大舞台和 112px 的大头像（列表头像缩到 56px，换来一屏能看到更多 Bot；大头像留给精选和详情页）；三列网格（改两列）；卡片悬停上浮 4px 和染色投影（改为不位移的光晕）；舞台光斑 18 秒漂移（砖是静止的，流动只留给 Hero 的极光）；气泡在头像上方（卡片里没有那块空间了，改到介绍那一格，尖角朝上）；浅色暖底作为主打（降为跟随系统的另一套 token）；墨色实底的「我要投稿」大按钮（降为搜索框下面的小玻璃胶囊，导航条里另有一枚实心按钮）。
    - **没放弃的**：货架保持官方色、不给灰色 Bot 换色（第 30 条）；可用性底线（键盘、读屏、触摸目标、对比度、减少动效）；全部 `data-testid` 和对 /submit 兼容的旧 token 名。
    - 列表卡的版式按卡片自己的宽度切换（容器查询），不看视口：/submit 的投稿预览只有 380px 宽，复用同一张卡时自动用窄版式。
32. **官方色近乎纯黑的 Bot，浅色主题下眼睛换成奶白**。第 30 条定的是「所有活体用恒定黑眼睛」，当时货架上没有黑色 Bot；后来上架的 Critiquito 官方色是 `#000000`，浅色主题下黑眼睛压在黑身体上完全看不见。规则和深色换色用同一条线（相对亮度 L < 0.04）：浅色主题这些 Bot 的 `--bz-eye` 换成 `#f1efe9`，深色主题身体已经换成奶白、眼睛照旧。只改眼睛颜色，不改官方色和形状。放弃「给它描一圈边」和「把身体调浅」：前者在 56px 的头像里看不清，后者等于篡改官方色。

## 2026-11-15 标签页图标

33. **标签页图标是一只随机变化的 Bot**（用户 2026-11-15 定：「做成一个随机变化的 bot」；编号 31、32 留给 Raycast 版式分支）。此前站点没有 favicon，浏览器显示默认的灰色地球。现在每次打开随机一只，开着时每 4–7 秒变成另一只，过渡时形状渐变、颜色沿色相过渡、中途眨一下眼；眼睛跟着鼠标看（用户同日追加：「做成眼睛跟着鼠标移动的那种」），按鼠标在视口里的位置分格取视线，不追求真实夹角，因为页面拿不到图标在屏幕上的位置；规格见 `INTERACTION.md` 第 13 节。帧由页面里那套 bloub 引擎出，画成 SVG 的 data 地址写进 `<link rel="icon">`；颜色用招牌的 7 种，形状取 16px 下认得出的 18 种。另配静态三件套（svg、ico、apple-touch-icon）兜底。放弃：只在打开时随机、之后不动（用户要的是「变化」）；像页面头像那样每帧都动（图标每换一次浏览器都要解码重画，停留期应当零开销）；取货架上真实 Bot 的官方色（有灰、黑、白，在标签栏上看不清）；用 canvas 出 PNG（SVG 在任何像素密度下都清楚，内容也能直接断言）；RGB 直接混色（互补色中间会出现一帧灰）。已知边界：后台标签页的变化频率受浏览器节流；Safari 未实测，预期显示静态图标。

## 2026-11-15 LB6：品牌招牌与官方配色分工

30. **招牌用固定彩色吉祥物，货架保持官方色**（用户 2026-11-15 定）。用户对照 Grok Bot App 认为上线后的页面仍偏灰白；原因是招牌复用最新 Bot，而真实货架中有两只官方灰色 Bot。招牌改为 `meta.mjs` 中独立的 7 只品牌吉祥物，橙色居中，橙/紫/青绿/琥珀/棕/粉/薄荷绿交错；窄屏保留中间 5 只。货架卡片、舞台、按钮仍尊重作者的官方配色，分类标签则按分类独立配色。所有活体改用恒定黑眼睛、attentif 正脸与紧凑 viewBox，让身体更饱满，兼顾 Grok 风格辨识度和动效可读性。放弃「给灰色 Bot 换色」以及「招牌继续取最新 Bot」：前者会歪曲作者选择，后者让品牌视觉受货架数量和颜色偶然分布影响。品牌可五颜六色，不以篡改真实 Bot 为代价；不复制官方形状路径或眼位，不修改 vendor。

## 2026-11-14 第一期（MVP）

1. **git 历史从零开始**。原仓库没有开源许可证，历史里有原作者的全部教程、图片、二维码；新历史从孤儿提交开始，原历史只在维护者本地备份，不推送。
2. **点击计数用 D1，不用 KV**。KV 免费版每天 1000 次写入，每次有效点击要写两次，一天只撑约 500 次，且最终一致、同 key 每秒一写，并发会丢计数。D1 免费版每天 10 万行写入，`n = n + 1` 原子。
3. **热度不分按钮**：同 IP 同 Bot 24 小时只算一次；按钮分别记录，算在先点的那个上。
4. **点击后排序不实时重排**，下次进入或切换排序才变，免得卡片在鼠标下跳走。
5. **上架时间用 `addedAt` 字段，不从 git 取**。浅克隆拿不到完整历史，squash 和 merge 两种合并方式算出的时间不同，本地和线上会不一致。
6. **外部收录（`external: true`）不强制 ROLE.md、DESIGN.md、skills 和截图**；作者没有 GitHub 时可以只填 `name`（可选 `url`）。
7. **部署用 Cloudflare Pages 的 Git 集成**，GitHub 里不放任何密钥；PR 检查用 GitHub Actions（只用 `pull_request` 触发）。
8. **默认头像用 bloub（MIT）按 slug 生成**，从上游按固定提交引入，不用原仓库里那份拷贝。原 Bot 直聘页的形态和交互手感保留，代码全部重写。
9. **许可证**：代码 MIT；`bots/` 投稿内容 CC BY 4.0，提交即同意；外部收录条目只含本站写的介绍和链接，不在 CC BY 范围内。
10. **`/api/stats` 第一期不加缓存**，D1 每天 500 万行读取够用；量起来再加短缓存。
11. **视觉沿用旧站风格**（产品定）：黑白墨色、黑底胶囊主按钮、漫画式描边 + 硬投影气泡、舞台光晕。只复刻视觉数值，代码全部自写，并修掉旧站的缺陷（两行台词压头像、对比度不足、触摸目标小等），见 `INTERACTION.md`。
12. **投稿内容按不可信处理**（独立代码审查后加固）：DESIGN.md 禁止 frontmatter 且渲染时绕开 gray-matter；不跟随符号链接；meta 走转义写法，name/tagline/pitch 禁止 `< > "`；外链图片只渲染成链接；文本文件 ≤100KB；`npm run build` 先校验；CI 检查外部贡献者只能改 `bots/`、不能改已上架 Bot 的 addedAt；计数接口只收 JSON、拒绝跨站来源、IPv6 按 /64 去重。
13. **x.ai 模板页的「Add to Grok Bot」是唤起桌面/手机 App 的 `grokbot://` 链接**，网页里没有导入动作；所以「一键导入」只负责打开模板页，导入发生在 App 里，站点拿不到导入成功的数据。

## 2026-11-14 S2：Issue 表单投稿

14. **用 Issue 表单作为无令牌投稿入口**。AI 只生成一个预填链接（BZB1 压缩包）；学员登录 GitHub 后拖图、勾公开授权、提交。URL 超过 7500 字符时降级成粘贴明文，不要求在网页分三次上传、不让 Grok 云电脑持有 GitHub 令牌。原有 PR 投稿入口继续保留；头像不进文本包，使用默认头像。
15. **特权工作流只执行默认分支可信代码，投稿始终是数据**。正文和身份经 env 传入，不做 shell 插值；解包限制路径、扩展名、文件数/大小和 gzip 输出，拒绝符号链接，git/gh 只用固定命令与参数数组。下载只接收 GitHub 附件，逐跳限制主机、时间、流量并查文件头。不采用执行投稿脚本、远程模板或特权 PR 事件的方案。
16. **Issue 作者就是投稿作者**。`author.github` 必须与 Issue login 一致（忽略大小写）；已有 slug 只允许原作者更新，addedAt 不变。每个 Issue 独占一个 `submission/issue-<号>` 分支，从默认分支重建单提交；提交作者为 Issue 用户的 noreply 身份，提交者是 Actions bot。通过前不创建分支/PR；错误沿用中文四项诊断，只更新本工作流带隐藏标记的 bot 评论。
17. **对第 7 条 CI 触发方式增加手动派发补充，不提高 CI 权限**。GITHUB_TOKEN 写入不会自动触发 PR CI，所以投稿工作流持有 `actions: write`，推分支/建 PR 后显式派发 `ci.yml`。CI 增加无输入的 `workflow_dispatch`，非 PR 事件按 CONTRIBUTOR 严格检查，job 名仍为 `validate-and-build`，仍需保护分支的一人批准和必需检查。保留现有 concurrency 配置，多个手动运行可能互相取消，作为真实联调已知边界单独跟进。
18. **机器校验不替代公开内容审核**。自动检查能证明格式、权限字段存在、密钥规则与图片头等，不保证截图真实、无隐私或模板链接匿名可访问。PR 只勾选已证实的校验/授权检查项，其余由维护者核验；不自动合并。不创建真实标签/Issue、不使用真实网络做测试，GitHub 权限、Issue 原生长度限制及附件跳转行为留给维护者联调。细节见 `ARCHITECTURE.md` 的 Issue 投稿一节。

## 2026-11-14 S3：网站直投

22. **网站投稿页 `/submit` 取代 Issue 表单成为主入口**，Issue 表单保留作备用（第 14 条降为备用入口）。学员在中文页面上预览、即时看到中文报错、拖截图、提交，进度也在本站显示。放弃：只用 Issue 表单（英文页面，提交后 1–2 分钟才知道对错）；不登录也能投（失去「贡献者」署名和防冒名）。
23. **登录用零 scope 的 OAuth App，写仓库用只装本仓库的 GitHub App。** 登录拿到 `/user` 后立即撤销用户令牌，会话 cookie 只存数字 id 和 login。GitHub App 只开 Contents、Pull requests 写和 Metadata 读，每次换令牌都降到这几项。放弃：GitHub App 的用户授权（授权页显示「Act on your behalf」，吓到学员）；OAuth `public_repo`（能写学员所有公开仓库）。
24. **推翻第一期「不做登录系统，以及除点击计数以外的任何后端」**，新增后端只限投稿：Pages Functions + D1 限流表。密钥只放 Cloudflare 加密变量，GitHub 里仍不放任何密钥（第 7 条不变）。
25. **推翻第 18 条「不自动合并」**：网站投稿 PR 一创建就开启自动合并（普通合并），维护者批准且 `validate-and-build` 通过后自动合入。前提：保留「推送新提交后旧批准作废」；要求代码所有者批准（`.github/CODEOWNERS`）；App 不在规则集绕过名单里。人工审核内容的要求不变。
26. **按 Cloudflare 免费版限额设计**（每请求 10ms CPU、50 个子请求、128MB 内存）：截图一张一个请求、传原始字节、用原生 base64；文本单独提交。超了先拆「校验」和「写入」两个接口，再考虑 Workers Paid。
27. **校验器拆成纯内核 + fs 适配器**，CLI、浏览器、Function 共用同一套规则和中文报错。Ajv 改为 standalone 预编译，生成文件提交进仓库，由测试保证和 schema 同步；它是派生物，不算第二份枚举。
28. **服务端统一改写 `author.github` 和 `addedAt`**：作者就是登录账号，学员不用再报 GitHub 用户名；新投稿取北京时间当天，更新沿用 main 上的原值。slug 归属以 main HEAD 上的 `bot.yaml` 为准，不信构建时的索引。校验和密钥扫描必须在推送之前完成（推送到公开仓库即公开）。
29. **上线通知以部署到的提交为准**：构建写 `/api-data/build.json`，`announce-live` 工作流等到它包含本次合并的提交、且详情页可访问，才在 PR（和来源 Issue）里评论「已上线」，然后删投稿分支。不以详情页返回 200 为准（更新已有 Bot 时它本来就是 200）。

## 2026-11-15 V5：设计系统

36. **设计系统 v5：界面中性、颜色只来自 Bot；按钮改为玻璃和实心两种，取消 Bot 色实底按钮。** 用户看了 v4 说「太粗糙，要顶级设计师的审美」，问题出在层级、间距、圆角、按钮、图标不成体系。v5 定下：字号 8 档、间距 9 档、圆角三档（8 / 12 / 16，头像砖 24%，分段控件是唯一的胶囊），每个数都落在阶梯上；按钮、标签、筛选、边框一律黑白灰，彩色只留给 Bot 身体、砖底柔光、悬停时透出来的 Bot 色和按钮的淡染，这样彩色才显眼；次级按钮是玻璃（在 Bot 范围里淡染 Bot 色），实心按钮一屏最多一个；卡片不用投影；全站一套线性图标；圆体只给标题、Bot 名和气泡。样式表按区域拆到 `theme/styles/`。放弃：每张卡一枚 Bot 色实底按钮（一屏几十个彩色按钮，抢了 Bot 的颜色，灰白黑的 Bot 还像禁用）；胶囊按钮和胶囊标签；首屏的斜向极光（糊在砖墙上发浑，改成砖墙背后的三团色光）。规格见 `INTERACTION.md` §0、§1、§1b。
